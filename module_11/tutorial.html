String & Array Operations

The rep prefix and the six string instructions — movsb, stosb, lodsb, scasb, cmpsb, insb/outsb — turn a complex loop into a single prefixed opcode. You will implement strlen, strcpy, memset, and memcmp in assembly and understand their security implications at the byte level.

Prerequisites — Module 10 (addressing modes), Module 07 (stack frames), Module 05 (bitwise, direction flag).

The Direction Flag and String Instructions

x86-64 has six "string" instructions that operate on a source pointer (rsi), a destination pointer (rdi), a count (rcx), and an accumulator (al/ax/eax/rax). After each operation, the CPU automatically increments or decrements rsi/rdi by the operand size, depending on the Direction Flag (DF).

InstructionWhat it does (one step)DF=0 (CLD)DF=1 (STD)
movsb[rdi] = [rsi]rsi++, rdi++rsi--, rdi--
stosb[rdi] = alrdi++rdi--
lodsbal = [rsi]rsi++rsi--
scasbflags = al - [rdi]rdi++rdi--
cmpsbflags = [rsi] - [rdi]rsi++, rdi++rsi--, rdi--
Convention
The System V AMD64 ABI requires DF=0 (cleared) at function entry and exit. Always call cld before string instructions unless you are certain DF is already clear. If you set DF with std, clear it immediately after with cld.

The REP Family of Prefixes

Adding rep before a string instruction makes it repeat: decrement rcx, execute, check termination condition. If rcx reaches zero, the instruction stops.

PrefixTerminationCommon use
reprcx == 0movsb (copy), stosb (fill)
repe / repzrcx == 0 OR ZF == 0cmpsb (compare while equal)
repne / repnzrcx == 0 OR ZF == 1scasb (scan until found)

strlen — Two Implementations

Manual Loop (most readable)

; asm_strlen(const char *s) → rax = length
asm_strlen:
    xor  rax, rax            ; rax = index (counter)
.loop:
    cmp  byte [rdi + rax], 0
    je   .done
    inc  rax
    jmp  .loop
.done:
    ret

Using repne scasb

; asm_strlen_rep(const char *s) → rax = length
asm_strlen_rep:
    mov  rcx, -1             ; scan up to 2^64 bytes
    xor  al, al              ; search for null byte
    repne scasb             ; while [rdi] != al: rdi++, rcx--
    ; After the loop: rcx started at -1 = 0xFFFF...FFFF
    ; and ended at (0xFFFF...FFFF - length - 1)
    ; So: ~rcx = length + 1 → ~rcx - 1 = length
    not  rcx
    dec  rcx
    mov  rax, rcx
    ret
Why not rcx; dec rcx?

rcx starts at -1 (all bits set). After scanning a string of length n, repne scasb decrements rcx once per character plus one more for the null terminator, so rcx = -1 - n - 1 = -n - 2. Taking ~rcx gives n + 1 (since ~(-n-2) = n+1). Subtracting 1 yields n. This is a standard idiom — you will see it in hand-optimized libc implementations.

memset — rep stosb

; asm_memset(void *dst, int val, size_t n)
asm_memset:
    ; rdi = dst, rsi = val, rdx = n
    mov  al, sil             ; al = fill byte (low 8 bits of val)
    mov  rcx, rdx            ; rcx = count
    rep  stosb               ; [rdi++] = al, rcx-- until rcx==0
    ret
Fast String Microcode
On modern Intel CPUs (Ivy Bridge+), rep stosb with a cache-line-aligned destination and large count triggers hardware-accelerated "fast string" operations that internally use 16 or 32-byte stores. The same applies to rep movsb. This makes the simple prefixed form competitive with explicit SSE2 implementations for many practical sizes.

memcmp — repe cmpsb

; asm_memcmp(const void *a, const void *b, size_t n) → rax
asm_memcmp:
    ; rdi = a, rsi = b, rdx = n
    mov  rcx, rdx
    xor  rax, rax
    test rcx, rcx
    jz   .done
    repe cmpsb              ; compare [rdi++] vs [rsi++] while equal
    je   .done               ; all bytes equal → rax = 0
    movzx eax, byte [rdi-1]  ; byte from a at mismatch
    movzx ecx, byte [rsi-1]  ; byte from b at mismatch
    sub  rax, rcx            ; return a_byte - b_byte
.done:
    ret
Security — Timing Side Channels in memcmp

repe cmpsb stops at the first mismatch — it returns early. This means comparing a password of 8 identical bytes is faster than comparing one that matches the first 7. An attacker who can measure the time of many comparisons can recover the expected value byte-by-byte. Cryptographic code must use constant-time comparison: compare all bytes unconditionally and only check the result at the end. The assembly pattern looks like:

; Constant-time compare of n bytes: no early exit
    xor  eax, eax
.loop:
    movzx r10d, byte [rdi]
    movzx r11d, byte [rsi]
    xor  r10d, r11d          ; 0 if equal, non-zero if different
    or   eax, r10d           ; accumulate diffs — no branch
    inc  rdi
    inc  rsi
    dec  rcx
    jnz  .loop
    ; rax == 0 iff equal

Scanning with repne scasb

; Find the index of a byte in a buffer
    lea  rdi, [rel buffer]
    mov  rcx, 256            ; max scan
    mov  al, 0x2C            ; search for ','
    repne scasb
    ; rdi now points one byte PAST the match
    ; rdi - buffer_base - 1 = index of matched byte
    lea  rbx, [rel buffer]
    sub  rdi, rbx
    dec  rdi                 ; rdi = zero-based index

Exercises

Warm-up

1. strrev — reverse a string in place

Implement asm_strrev(char *s). Use asm_strlen to find the end, then walk two pointers (one from the start, one from the end) inward, swapping bytes. Stop when they meet or cross. Test with "Hello" → "olleH".

Core

2. strncpy with explicit null-padding

Implement asm_strncpy(char *dst, const char *src, size_t n): copy at most n bytes from src to dst; if src is shorter than n, pad the rest of dst with null bytes. Use rep movsb for the copy part and rep stosb for the padding. This null-padding behavior is the C standard definition and prevents uninitialized-memory information leaks in fixed-size buffers.

Stretch

3. Constant-time memcmp

Implement the constant-time comparison pattern shown in the security callout above. Then verify that both the early-exit repe cmpsb version and your constant-time version return the same result for equal strings and unequal strings. Under GDB, use stepi to count the number of instructions executed by each version on: (a) identical strings, (b) strings that differ in the first byte, (c) strings that differ in the last byte. Confirm that your constant-time version executes the same instruction count in all three cases.
