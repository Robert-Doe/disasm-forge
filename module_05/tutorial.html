Why Bitwise Operations Are a Security Fundamental

Every low-level security primitive relies on bitwise operations. Stream cipher keystreams are XORed with plaintext. Hash functions use rotates, shifts, and XORs. Permission bits in page table entries are set and cleared with AND and OR. CPU feature flags (from CPUID) are extracted with AND and shift. Shellcode is often XOR-encoded to avoid null bytes. Exploit mitigations like ASLR add entropy using bit shifts. Understanding these operations at the instruction level means you can read crypto implementations, understand hardware interfaces, and see through obfuscation.

Shifts: Moving Bits Left and Right

Shifts move all bits in a register a specified number of positions. The vacated positions are filled with either 0 or the sign bit. The bit that falls off the end goes into CF.

InstructionFill vacated bits withUse case
shl rax, N0 on rightMultiply by 2ᴺ (unsigned/signed)
shr rax, N0 on leftDivide by 2ᴺ (unsigned only)
sar rax, NSign bit on leftDivide by 2ᴺ (signed — preserves negativity)
Critical Distinction: SHR vs SAR on Negative Numbers
mov  rax, -128     ; 0xFFFFFFFFFFFFFF80
sar  rax, 3        ; = -16   fills with 1s (sign bit) → 0xFFFFFFFFFFFFFFF0
shr  rax, 3        ; = 2305843009213693936  fills with 0s → 0x1FFFFFFFFFFFFFF0
If you use shr on a signed value, you get a large positive number instead of the expected negative result. In disassembly, seeing sar tells you the value is treated as signed; shr tells you it is unsigned.

Rotates: Circular Shifts

Unlike shifts, rotates do not discard the bits that fall off the edge — they wrap around to the other side. rol (rotate left) and ror (rotate right) are heavily used in cryptographic hash functions (SHA-256, ChaCha20).

rol  rax, 1   ; bit 63 → bit 0, all others shift left by 1
ror  rax, 1   ; bit 0 → bit 63, all others shift right by 1

; rcl/rcr: rotate THROUGH the carry flag (CF participates as an extra bit)
rcl  rax, 1   ; bit 63 → CF, old CF → bit 0
rcr  rax, 1   ; bit 0 → CF, old CF → bit 63

Bit Test Instructions

These instructions test a single bit and optionally modify it, copying the original bit value to CF. They are used constantly in OS code for manipulating hardware register fields and page table entries.

bt   rax, 5   ; test bit 5 of rax → CF = value of bit 5 (rax unchanged)
bts  rax, 5   ; test bit 5, then SET it to 1 → CF = old value
btr  rax, 5   ; test bit 5, then RESET (clear) it → CF = old value
btc  rax, 5   ; test bit 5, then COMPLEMENT (toggle) it → CF = old value

Bit Scan: Finding the First Set Bit

bsf  rbx, rax   ; Bit Scan Forward: rbx = index of lowest set bit in rax
bsr  rbx, rax   ; Bit Scan Reverse: rbx = index of highest set bit in rax
; WARNING: if rax = 0, result is UNDEFINED and ZF=1

Advanced Bit Instructions (BMI)

popcnt rbx, rax  ; rbx = number of 1-bits in rax (population count)
tzcnt  rbx, rax  ; rbx = number of trailing zeros (lowest N bits are 0)
lzcnt  rbx, rax  ; rbx = number of leading zeros
Security Use — POPCNT in Crypto
popcnt appears in implementations of Hamming weight (number of differing bits between two values), which is used in error-correcting codes and in measuring cryptographic distance. It also appears in timing-attack-resistant code where branch-free implementations use popcnt to avoid conditional branches that leak secret data through timing.

Practical Security Bit Patterns

; 1. Extract lower nibble (bits 3:0) from a byte
and  rax, 0x0F             ; mask all but lower 4 bits

; 2. Extract upper nibble (bits 7:4) from a byte
shr  rax, 4                ; shift upper nibble to position 0

; 3. Fast unsigned divide by power of two
shr  rax, 3                ; rax / 8  (3 = log2(8))

; 4. Test if N is a power of two: (N & (N-1)) == 0
mov  rbx, rax
dec  rbx
and  rbx, rax              ; if result == 0, rax is a power of two

; 5. Set bit N: use OR with a shifted 1
mov  rcx, 5               ; bit position
mov  rbx, 1
shl  rbx, cl              ; cl = low 8 bits of rcx — shift amount
or   rax, rbx             ; set bit 5
Tip — cl for Variable Shift Count
When the shift count is stored in a register (not known at assembly time), you must use the cl register (the low byte of rcx) as the shift operand. You cannot use shl rax, rbx — the architecture only allows cl or an immediate. This is why compilers move variable shift amounts into rcx before shifting.

Exercises

Warm-up

1. Bit manipulation by hand

Without running the code, compute: (a) 0xABCD & 0x0F0F, (b) 0x1234 | 0x8000, (c) 0xFF ^ 0xAA. Then add each to bits.asm and verify your answers.

Core

2. Extract all four bytes from a 32-bit value

Given rax = 0x12345678, use shifts and masks to extract each byte (0x12, 0x34, 0x56, 0x78) into separate registers and print them. This is the kind of operation used in network packet parsing.

Core

3. Implement a byte swap (bswap)

x86-64 has a bswap rax instruction that reverses the byte order. First implement byte-swap manually using shifts and ORs, then replace it with bswap and confirm the output is identical. bswap is used for network-to-host byte order conversion.

Stretch

4. Branchless absolute value

Compute the absolute value of a signed integer without using any jump instructions. Hint: arithmetic right shift by 63 produces either all-zeros (positive) or all-ones (negative). Use that mask with XOR and subtraction. This technique appears in constant-time cryptographic code.
