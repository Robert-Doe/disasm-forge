x87 FPU & SSE2 Scalar Floating Point

Leave the integer pipeline behind. SSE2 scalar instructions process one IEEE 754 double at a time using xmm registers. The legacy x87 FPU stack still appears in old disassembly. Together they cover every floating-point pattern you will encounter in real binaries.

Prerequisites — Module 09 (ABI: float arguments in xmm), Module 03 (IEEE 754 bit layout in .data).

IEEE 754 Double-Precision Recap

Every double is 64 bits with three fields:

S
Exponent (11 bits)
Mantissa / Significand (52 bits)
  • Sign (bit 63): 0 = positive, 1 = negative
  • Exponent (bits 62–52): biased by 1023. A stored value of 1023 means 2⁰ = 1.
  • Mantissa (bits 51–0): the fractional part of the significand. The leading 1 bit is implicit (not stored) for normalized numbers.

Special values: all-zero exponent = zero/denormal; all-one exponent with zero mantissa = ±infinity; all-one exponent with nonzero mantissa = NaN.

Bit manipulation of floats — security relevance
Because a double is just 64 bits in memory, you can load it with mov rax, [addr] and inspect or forge individual fields with integer bitwise instructions. Type confusion vulnerabilities in JIT engines (V8, SpiderMonkey, JavaScriptCore) frequently abuse this: an attacker forces an engine to treat a crafted float's bit pattern as a pointer, or vice versa. Module 12 gives you the bit-level intuition to follow those exploits.

The xmm Registers

SSE2 adds 16 registers: xmm0–xmm15 (128 bits each). For scalar double work, only the low 64 bits are used. The high 64 bits are preserved but irrelevant.

Register rangeABI role (System V)ABI role (Windows x64)
xmm0–xmm7Argument 1–8 (float/double), also return value in xmm0Argument 1–4 (xmm0–xmm3), return in xmm0
xmm8–xmm15Caller-saved (scratch)xmm8–xmm15 caller-saved; xmm6–xmm15 callee-saved for non-volatile use

Float Arithmetic in Assembly

; 1.0 + 2.0 = 3.0
    movsd xmm0, [rel val_1_0]   ; xmm0 = 1.0
    movsd xmm1, [rel val_2_0]   ; xmm1 = 2.0
    addsd xmm0, xmm1            ; xmm0 = 3.0

; Integer to double and back
    mov    rax, 42
    cvtsi2sd xmm0, rax          ; xmm0 = 42.0

    movsd xmm0, [rel val_pi]    ; xmm0 = 3.14159...
    cvttsd2si rax, xmm0         ; rax = 3 (truncated)

Floating-Point Comparisons with ucomisd

    movsd xmm0, [rel a]
    movsd xmm1, [rel b]
    ucomisd xmm0, xmm1          ; compare a vs b
    ja  .a_greater              ; a > b (unsigned above = CF=0 and ZF=0)
    je  .equal                  ; a == b (ZF=1, CF=0)
    jb  .b_greater              ; a < b (CF=1)
    jp  .unordered              ; one operand is NaN (PF=1)
NaN Propagation
Any arithmetic with NaN produces NaN. ucomisd with a NaN sets PF=1 (parity flag). The condition jp (jump if parity) is how you detect NaN after a comparison. Forgetting to check PF on NaN inputs is a common source of incorrect floating-point comparisons in hand-written assembly.

The x87 FPU Stack

The x87 FPU predates SSE2. It is a stack of eight 80-bit extended-precision registers (st0–st7). Unlike SSE2, operations always involve st0 (the top of stack). The stack is still used by fsin, fcos, ftan, fprem, and other transcendentals not available in SSE2.

; Compute 2 * pi using x87
    fld  qword [rel pi]          ; push: st0 = pi
    fld  qword [rel two]         ; push: st0 = 2.0, st1 = pi
    fmulp                        ; st0 = st0 * st1, pop → st0 = 2*pi
    sub  rsp, 8
    fstp qword [rsp]             ; pop st0 into memory
    movsd xmm0, [rsp]            ; bring into xmm for SSE use
    add  rsp, 8

; sin(pi) using x87
    fld  qword [rel pi]          ; st0 = pi
    fsin                         ; st0 = sin(pi) ≈ 1.2e-16 (float rounding)
    fstp qword [rsp-8]           ; (inside a leaf, red zone)

Dot Product Implementation

; asm_dot3(const double *a, const double *b) → xmm0 = a·b
asm_dot3:
    movsd xmm0, [rdi]           ; xmm0 = a[0]
    mulsd xmm0, [rsi]           ; xmm0 = a[0]*b[0]

    movsd xmm1, [rdi+8]         ; a[1]
    mulsd xmm1, [rsi+8]         ; a[1]*b[1]

    movsd xmm2, [rdi+16]        ; a[2]
    mulsd xmm2, [rsi+16]        ; a[2]*b[2]

    addsd xmm0, xmm1            ; sum first two products
    addsd xmm0, xmm2            ; add third → return in xmm0
    ret

Exercises

Warm-up

1. Inspect IEEE 754 bit patterns

Store 1.0, -1.0, 0.0, and Infinity (dq 0x7FF0000000000000) in .data. Load each with mov rax, [rel label] (integer load) and print the raw hex with print_u64. Verify: 1.0 = 0x3FF0000000000000, -1.0 = 0xBFF0000000000000, 0.0 = 0x0.

Core

2. Implement fabs and fneg without x87

The sign bit is bit 63. Implement absolute value by clearing bit 63 (and rax, 0x7FFFFFFFFFFFFFFF) and negate by toggling bit 63 (xor rax, 0x8000000000000000). Move the result back into xmm via memory (mov [rsp-8], rax; movsd xmm0, [rsp-8]) and verify with print_f64. This is exactly how compilers implement fabs and unary negation without a dedicated instruction.

Stretch

3. Implement Horner's method for polynomial evaluation

Evaluate the polynomial p(x) = 3x³ + 2x² + x + 5 at x = 2.0 using Horner's form: ((3x + 2)x + 1)x + 5. Store the coefficients as a dq array [3.0, 2.0, 1.0, 5.0]. Write a loop that reads from the array and applies one mulsd + addsd per iteration. Expected result: 3×8 + 2×4 + 2 + 5 = 24 + 8 + 2 + 5 = 39.0.
