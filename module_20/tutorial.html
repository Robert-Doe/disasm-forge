Bare-Metal Runtime

No C runtime. No libc. No main called by someone else. The kernel hands control to _start and everything after that is yours: stack setup, heap initialization, I/O, and exit — all in assembly.

Prerequisites — Module 15 (syscalls, mmap/brk), Module 16 (linker, symbols), Module 08 (stack discipline, callee-saved registers).

What You Will Build

  • runtime/start.asm — _start: reads initial stack, aligns rsp, calls heap_init and our_main, calls sys_exit
  • runtime/syscall_wrappers.asm — thin C-ABI wrappers around 8 Linux syscalls
  • runtime/alloc.asm — heap_init + bump_alloc: monotonic allocator via sys_brk
  • runtime/io.asm — io_write_str, io_write_u64, io_write_hex, our_main

What Happens Between execve and main()

When you run any program, the kernel does not jump directly to main. It jumps to the ELF entry point (e_entry), which is _start in the C runtime startup object (crt1.o). The C runtime's _start then does considerable work before calling main:

  1. Reads argc, argv, envp from the initial kernel stack
  2. Aligns rsp to 16 bytes
  3. Calls global constructors (__init_array)
  4. Initialises the heap (malloc internals)
  5. Sets up locale, signal handlers, atexit
  6. Calls __libc_start_main(main, argc, argv, ...)
  7. After main returns: calls atexit handlers, flushes stdio, calls _exit

Our bare-metal _start skips steps 3–7 entirely. That is not a flaw — it is a feature when building minimal tools.

_start Implementation

_start:
    pop  rdi               ; rdi = argc
    mov  rsi, rsp           ; rsi = &argv[0]  (rsp now points here after pop)
    lea  rdx, [rsi + rdi*8 + 8]  ; rdx = &envp[0]

    ; Align stack: after pop, rsp = original_rsp+8
    ; We need rsp % 16 == 0 BEFORE 'call' (which pushes 8 more)
    ; So we want rsp % 16 == 8 here.
    and  rsp, ~0xF          ; round down to 16-byte boundary
    sub  rsp, 8              ; now rsp % 16 == 8, ready for call

    call heap_init
    call our_main           ; rdi/rsi/rdx already set from above

    mov  rdi, rax            ; exit code from our_main
    mov  rax, 60             ; SYS_EXIT
    syscall

Syscall Wrapper Pattern

; sys_write(fd, buf, count) — the 4th-arg problem does not apply here
sys_write:
    mov  rax, 1              ; SYS_WRITE
    syscall
    ret

; sys_mmap has 6 args; the 4th (flags) arrives in rcx but syscall wants r10
sys_mmap:
    mov  r10, rcx           ; flags: rcx → r10
    mov  rax, 9              ; SYS_MMAP
    syscall
    ret

Bump Allocator — sys_brk Based

; heap_init: call sys_brk(0) to get current break, then extend by 64 KiB
heap_init:
    xor  rdi, rdi
    call sys_brk            ; rax = current break
    mov  [rel heap_base], rax
    mov  [rel heap_ptr],  rax
    add  rax, 65536
    mov  rdi, rax
    call sys_brk            ; extend break by 64 KiB
    mov  [rel heap_end], rax
    ret

; bump_alloc(size): round up to 8, return heap_ptr, advance heap_ptr
bump_alloc:
    add  rdi, 7              ; round up to next multiple of 8
    and  rdi, ~7
    mov  rax, [rel heap_ptr]
    mov  rcx, rax
    add  rcx, rdi           ; new heap_ptr
    cmp  rcx, [rel heap_end]
    ja   .oom
    mov  [rel heap_ptr], rcx
    ret                     ; rax = allocated block
Why bump allocation with no free()?
A bump allocator has O(1) allocation with zero overhead per object. There is no free list, no metadata per allocation, no fragmentation. For programs that allocate during startup and then run until exit, bump allocation is optimal. This is why many language runtimes (Go's goroutine stacks at creation, some garbage collectors' nursery generations) use arena/bump allocation for short-lived objects.

Exercises

Warm-up

1. Print all argv and envp

Extend our_main in io.asm to loop through all argv entries (until the NULL sentinel) and print each one on its own line using io_write_str + io_newline. Then do the same for the first 5 envp entries. Verify: ./runtime_demo foo bar baz should print all three arguments.

Core

2. Implement io_write_s64 (signed decimal)

Add io_write_s64(int64_t n) to io.asm. If n < 0, write a '-' character then call io_write_u64(-n). Handle the edge case: INT64_MIN = -9223372036854775808 cannot be negated (negation overflows int64_t). For that specific value, write the string literal directly. Test with 0, -1, -42, INT64_MIN.

Stretch

3. Implement io_read_line and a simple echo loop

Add size_t io_read_line(char *buf, size_t max) that calls sys_read(STDIN_FILENO, buf, max) and returns the number of bytes read. In our_main, loop: allocate a 256-byte buffer via bump_alloc, call io_read_line, write the result back with sys_write. Exit when zero bytes are read (EOF). Test: echo "hello from stdin" | ./runtime_demo. You have now built a complete read-process-write loop with no libc whatsoever.

The final module synthesizes the entire course into one project: a length-disassembler for x86-64 instructions written in pure assembly.
