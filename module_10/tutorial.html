Memory Addressing Modes

Five ways to tell the CPU where to find data — from a constant baked into the instruction to [base + index×scale + displacement] — plus LEA tricks and RIP-relative position-independent access.

Prerequisites — Modules 01–09: ABI complete, stack frames solid, data sections understood.

What You Will Build

  • addressing.asm — exercises all five addressing modes, LEA arithmetic tricks, RIP-relative access, size-override loads, and a complete 2D array walk
  • The ability to decode any memory operand you encounter in disassembly

Why Addressing Modes Matter for Security

Understanding addressing modes is how you read disassembly. Every memory access in a compiled binary uses one of these five forms. When you see mov rax, [rbx + rcx*8 + 16] in IDA or Ghidra, you need to instantly know: this loads 8 bytes from address rbx + rcx×8 + 16. If rcx is attacker-controlled, the question becomes: what address can the attacker make this instruction read from? How far can rcx reach? Can they make it read past array bounds? These questions are only answerable if you fully understand addressing modes.

The Five Addressing Mode Families

1. Immediate

The value is embedded directly in the instruction's encoding. No memory is accessed.

mov rax, 42         ; 42 is part of the instruction bytes
add rax, 0xFF       ; immediate operand

2. Register

The value comes from a register. The fastest possible operand — no memory bus involved.

mov rax, rbx       ; value from register — zero latency

3. Direct (Absolute Address)

The instruction encodes a fixed memory address. In 64-bit code this is usually expressed as a RIP-relative offset (see below) rather than a literal 64-bit address, because 64-bit absolute addresses require a REX prefix and 8 extra bytes of encoding.

mov rax, [rel my_var]   ; read 8 bytes at the address of my_var

4. Register-Indirect

The address is stored in a register. The instruction reads from that address.

mov rax, [rbx]        ; read from the address stored in rbx
mov [rdi], rcx        ; write rcx to the address stored in rdi

5. Scaled-Index (the Most Powerful Form)

The full x86-64 addressing formula: [base + index * scale + displacement]

  • base: any 64-bit register
  • index: any 64-bit register except rsp
  • scale: must be exactly 1, 2, 4, or 8 (encoded in 2 bits of the SIB byte)
  • displacement: signed 8-bit or 32-bit constant (0 if omitted)
; Access array[i] where each element is 8 bytes (scale=8)
mov  rax, [rbx + rcx*8]

; Access struct array: each struct is 24 bytes — must compute manually
imul rcx, 24                    ; scale not 1/2/4/8, so pre-multiply
mov  rax, [rbx + rcx + 8]      ; base + pre-multiplied index + field offset

; 2D array: int32_t a[3][4]  — access a[row][col]
; element index = row*4 + col
imul rax, 4                     ; row * COLS
add  rax, rcx                   ; + col = element index
mov  eax, [rbx + rax*4]        ; * sizeof(int32_t) = 4
Security Insight — Out-of-Bounds Reads
In the pattern [base + index*scale], if index is attacker-controlled with no bounds check, the attacker can compute what address the load will read from. With scale=8 and a 64-bit index, the reachable address range is enormous. Many CVEs are exactly this: a length field controls the index, the bounds check is bypassed (signed/unsigned confusion, off-by-one), and arbitrary memory is read or written.

LEA: Address Arithmetic Without a Memory Access

lea dst, [expr] (Load Effective Address) computes the value of the bracket expression and stores it in dst — but it never reads from memory. It is pure arithmetic performed by the address generation unit (AGU), which runs in parallel with the ALU. This makes lea a fast way to do multi-operand arithmetic.

GoalUsing leaEquivalent arithmetic
Multiply by 3lea rax, [rdi + rdi*2]rax = rdi + rdi×2 = rdi×3
Multiply by 5lea rax, [rdi + rdi*4]rax = rdi + rdi×4 = rdi×5
Multiply by 9lea rax, [rdi + rdi*8]rax = rdi + rdi×8 = rdi×9
Add 3 valueslea rax, [rbx + rcx + 16]rax = rbx + rcx + 16
Get array addresslea rax, [rbx + rdi*4]rax = &array[i] (no load)

RIP-Relative Addressing

In 64-bit Position-Independent Executables (PIE), the binary can load at any address chosen by ASLR. Absolute addresses are useless — the data's address changes every run. Instead, the CPU computes data addresses relative to the current instruction pointer (rip).

; [rel label] encodes as: [rip + (label - next_instruction)]
; The offset is fixed at link time; the absolute address varies per run
lea  rax, [rel my_string]   ; rax = current address of my_string
mov  rbx, [rel my_var]      ; rbx = value at current address of my_var
Tip — default rel in NASM
Put default rel at the top of your NASM file to make all [] memory accesses RIP-relative by default. Then you don't need to write rel on every access. This matches the output of GCC for PIE binaries.

Size Overrides: BYTE, WORD, DWORD, QWORD

movzx rax, byte  [rbx]    ; load 1 byte, zero-extend → 64 bits
movzx rax, word  [rbx]    ; load 2 bytes, zero-extend
movsx rax, dword [rbx]    ; load 4 bytes, sign-extend (for signed int)
mov   eax,       [rbx]    ; load 4 bytes, zero-extend (eax write zeroes upper 32)
mov   rax,       [rbx]    ; load 8 bytes

Exercises

Warm-up

1. Compute all addresses manually

For the 3×4 array of int32_t in .data, compute the byte offset of every element from the base address on paper. Verify by running the program under GDB, setting a breakpoint at the 2D walk loop, and checking that the computed address matches your calculation each iteration.

Core

2. Access a struct field using displacement

Define a struct in .data as three consecutive qwords: dq 100, 200, 300. Using lea rbx, [rel struct_base], access each field using displacements: [rbx+0], [rbx+8], [rbx+16]. Then define an array of 3 such structs (9 qwords) and access array[1].field2 using [rbx + 1*24 + 8] where 24 = struct size and 8 = field2 offset.

Core

3. LEA multiply benchmark

Implement multiply-by-7 using LEA (hint: 7 = 8 - 1, so lea rax, [rdi*8] then sub rax, rdi). Implement multiply-by-25 (25 = 5×5, so use two LEA instructions). Verify both with known inputs.

Stretch

4. Walk a linked list

Define three nodes in .data, each as two qwords: dq value, next_ptr. Set the last node's next_ptr to 0 (null). Walk the list starting from the first node using register-indirect: mov rax, [rbx] (value), mov rbx, [rbx+8] (next). Print each value and stop when rbx == 0.
