Caller-Saved vs Callee-Saved Registers

The ABI divides the 16 general-purpose registers into two groups based on who is responsible for preserving their values across a function call.

TypeRegisters (Linux/macOS)Rule
Caller-savedrax rcx rdx rsi rdi r8 r9 r10 r11May be destroyed by any function you call. Save them yourself before calling if you need them afterward.
Callee-savedrbx rbp r12 r13 r14 r15Must be preserved by any function that uses them. Push at entry, pop before ret.

The split is designed so that simple functions can use caller-saved registers freely without any save/restore overhead, while callee-saved registers provide a stable set of "working registers" across calls. If a function needs a value to survive across multiple nested calls, it stores that value in a callee-saved register.

; Correct use of callee-saved r12 in a function:
my_func:
    push rbp
    mov  rbp, rsp
    push r12          ; ← save r12 before using it
    push rbx          ; ← save rbx before using it

    mov  r12, rdi     ; store first arg in r12 (survives calls)
    call something    ; rdi/rsi/rax may be destroyed — r12 is safe
    add  rax, r12     ; use r12 after the call

    pop  rbx          ; ← restore in reverse order
    pop  r12          ; ← restore r12
    pop  rbp
    ret
Pop in Reverse Order
Push and pop use the same stack pointer. If you push r12 then rbx, you must pop rbx then r12 — in reverse order. Getting this wrong silently corrupts register values and produces impossible-to-debug behaviour. Always match your pushes and pops like parentheses.

Recursive Functions in Assembly

Recursion in assembly works the same as in any language — each call gets its own stack frame with its own copy of local variables. The key challenge is that arguments passed in registers (like rdi) will be overwritten by the recursive call. You must save them to callee-saved registers or to the stack first.

; fibonacci(n) — n arrives in rdi
fibonacci:
    push rbp
    mov  rbp, rsp
    push r12           ; callee-saved: will survive the recursive calls
    push rbx           ; callee-saved: will hold fib(n-1)

    mov  r12, rdi      ; r12 = n  (safe across calls)

    cmp  r12, 1
    jle  .base         ; fib(0)=0, fib(1)=1

    lea  rdi, [r12-1]  ; arg = n-1
    call fibonacci
    mov  rbx, rax      ; rbx = fib(n-1)  (r12 still holds n)

    lea  rdi, [r12-2]  ; arg = n-2
    call fibonacci     ; rax = fib(n-2)
    add  rax, rbx      ; rax = fib(n-1) + fib(n-2)
    jmp  .done

.base:
    mov  rax, r12      ; return n (0 or 1)
.done:
    pop  rbx
    pop  r12
    pop  rbp
    ret

Tail-Call Optimisation

A tail call is a recursive call that is the last thing the function does — the return value of the recursive call is returned unchanged. In this case, the current stack frame is no longer needed when the recursive call executes. Instead of call + ret (which would add a new frame), you can jmp back to the start of the function, reusing the existing frame. This reduces stack usage from O(n) to O(1).

; Tail-recursive sum: sum_to(n, acc) = sum_to(n-1, acc+n)  if n>0
;                                     = acc                   if n==0
sum_to_tail:
    ; rdi=n, rsi=acc — no prologue needed for a tail-only function
    test rdi, rdi
    jz   .done         ; n==0: return acc
    add  rsi, rdi      ; acc += n
    dec  rdi           ; n--
    jmp  sum_to_tail   ; ← JMP not CALL: no new frame, O(1) stack
.done:
    mov  rax, rsi
    ret
Insight — Tail Calls in Disassembly
When reversing a binary, a function that ends with jmp other_function instead of call other_function; ret is performing a tail call. The called function will execute and its ret will return directly to the original caller — skipping the current function entirely. This is important when tracing control flow in IDA or Ghidra: a jmp at the end of a function is not necessarily an unconditional branch to local code — it may be a tail call to another function.

The Red Zone

The System V AMD64 ABI (Linux/macOS) defines a red zone: the 128 bytes immediately below rsp (addresses [rsp-1] through [rsp-128]) that leaf functions (functions that make no further calls) may use as scratch space without adjusting rsp. The ABI guarantees that signal handlers will not use this area.

; Leaf function using the red zone — no sub rsp needed
fast_leaf:
    ; No prologue, no sub rsp
    mov  qword [rsp-8],  0x1111   ; local variable 1 in red zone
    mov  qword [rsp-16], 0x2222   ; local variable 2 in red zone
    mov  rax, [rsp-8]
    add  rax, [rsp-16]
    ret                              ; rsp never changed
Red Zone Does NOT Exist on Windows
The Microsoft x64 ABI has no red zone. Code that uses [rsp-N] without adjusting rsp will be silently corrupted by hardware interrupts and OS callbacks on Windows. This is a common porting bug when moving Linux assembly to Windows. Always use sub rsp, N before using local storage when writing cross-platform code.

Returning Multiple Values

The ABI allows functions to return up to two 64-bit values: the first in rax, the second in rdx. This is used for 128-bit integers and for functions that naturally produce two results (like division).

divmod:               ; returns: rax=quotient, rdx=remainder
    mov  rax, rdi   ; dividend
    xor  rdx, rdx   ; zero upper half
    div  rsi        ; rax=quotient, rdx=remainder — two values for free
    ret

Exercises

Warm-up

1. Trace fibonacci(5) by hand

Draw the call tree for fibonacci(5) on paper. Count how many total calls are made. Then set a breakpoint on the first instruction of fibonacci and use GDB's commands feature to print a counter each time it fires: break fibonacci, commands, silent, set $count=$count+1, printf "call #%d\n",$count, continue, end. Does the count match your tree?

Core

2. Corrupt a callee-saved register deliberately

Modify fibonacci to use r12 but NOT save/restore it (remove the push r12 / pop r12 pair). Set r12 = 0x12121212 in main before calling fibonacci. After the call, print r12. Is it still 0x12121212? This demonstrates what "callee-saved" means when violated — a category of real bugs.

Core

3. Convert recursive fibonacci to memoised

Add a 100-element array in .bss as a memo table. Before computing fibonacci(n), check if the result is already stored. If yes, return it immediately. If no, compute it, store it, then return. This changes the complexity from O(2ⁿ) to O(n). Verify fibonacci(40) returns instantly.

Stretch

4. Implement Ackermann(3, 6) with tail-call where possible

The Ackermann function is deeply recursive. Implement it and observe the stack depth in GDB. Use info frame to find the call depth. Then add a counter (a global in .bss) that increments on every call and print it at the end. Compare the call count for Ackermann(3,4) vs Ackermann(3,5).
