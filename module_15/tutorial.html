System Calls & Direct OS Interaction

The C library is gone. One instruction — syscall — transfers control to the kernel. You will call write, read, open, mmap, mprotect, and exit in pure assembly with no runtime at all. On Windows, the equivalent path goes through VirtualAlloc and WriteConsoleA at the Win32 API level.

Prerequisites — Module 09 (Linux ABI, register conventions), Module 14 (ELF entry point, _start).

What You Will Build

  • syscalls.asm — Linux: write/read/open/close/mmap/mprotect/munmap/brk/exit via syscall, linked with ld (zero libc)
  • win_api.asm — Windows: WriteConsoleA, VirtualAlloc, VirtualProtect, VirtualFree via Win32 imports

How Syscalls Work

User-space programs cannot touch hardware, kernel memory, or other processes directly. The only way to interact with the OS is through a controlled gate: the system call. On x86-64 Linux, issuing syscall causes the CPU to:

  1. Save rip (return address) into rcx
  2. Save rflags into r11
  3. Switch to ring 0 (kernel mode)
  4. Jump to the kernel's syscall handler (address from LSTAR MSR)
  5. The kernel reads rax to identify which syscall, reads arguments from registers, performs the operation, returns result in rax
  6. Execute sysret: restore rip from rcx, rflags from r11, switch back to ring 3
rcx is destroyed by syscall
The SYSCALL instruction writes the return address into rcx, overwriting whatever was there. The Linux syscall ABI therefore uses r10 for the 4th argument instead of rcx. This differs from the System V function call ABI where rcx is the 4th argument register. Never put a syscall's 4th argument in rcx — it will be gone when the kernel reads it.

sys_write — Printing Without stdio

; write(STDOUT=1, buf, len)
    mov  rax, 1               ; SYS_WRITE
    mov  rdi, 1               ; fd = STDOUT
    lea  rsi, [rel message]  ; buf
    mov  rdx, 25              ; len
    syscall                   ; rax = bytes written, or -errno

sys_open + sys_read + sys_close — File I/O

; open("/tmp/file", O_WRONLY|O_CREAT|O_TRUNC, 0644)
    mov  rax, 2               ; SYS_OPEN
    lea  rdi, [rel path]     ; const char *pathname (null-terminated)
    mov  rsi, 0x241           ; O_WRONLY|O_CREAT|O_TRUNC
    mov  rdx, 0o644           ; mode (NASM octal literal)
    syscall
    mov  r12, rax             ; save fd (r12 = callee-saved across syscall)

; read(fd, buf, 64)
    mov  rax, 0               ; SYS_READ
    mov  rdi, r12             ; fd
    lea  rsi, [rel read_buf] ; buffer
    mov  rdx, 64              ; max bytes
    syscall                   ; rax = bytes actually read

; close(fd)
    mov  rax, 3               ; SYS_CLOSE
    mov  rdi, r12
    syscall

sys_mmap — The Shellcode Loader Pattern

; mmap(NULL, 4096, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANON, -1, 0)
    mov  rax, 9               ; SYS_MMAP
    xor  rdi, rdi             ; addr = NULL (OS chooses)
    mov  rsi, 4096            ; size = one page
    mov  rdx, 3               ; PROT_READ | PROT_WRITE
    mov  r10, 0x22            ; MAP_PRIVATE | MAP_ANONYMOUS (4th arg = r10!)
    mov  r8, -1               ; fd = -1
    xor  r9, r9               ; offset = 0
    syscall                   ; rax = mapped address
    mov  r14, rax             ; save mapped address

; --- write payload bytes into the RW page ---

; mprotect(addr, 4096, PROT_READ|PROT_EXEC)  -- make it executable
    mov  rax, 10              ; SYS_MPROTECT
    mov  rdi, r14
    mov  rsi, 4096
    mov  rdx, 5               ; PROT_READ | PROT_EXEC
    syscall

; Now [r14] contains executable code — call it
    call r14                  ; jump into the shellcode
Security — W^X (Write XOR Execute)

The sequence above is how shellcode loaders work: allocate writable memory, write machine code into it, flip it executable, call it. Modern mitigations interrupt this chain:

  • NX/DEP — hardware enforcement: the CPU refuses to execute pages without the execute bit. mmap(PROT_WRITE) pages are not executable by default.
  • W^X — OS policy: a page may be writable OR executable but not both simultaneously. mprotect fails if you try to set PROT_WRITE|PROT_EXEC.
  • SELinux/AppArmor mmap rules — policy can deny mmap(PROT_EXEC) entirely for certain processes.
  • Intel CET (Control-flow Enforcement Technology) — shadow stack + indirect branch tracking makes ROP/JOP much harder.

sys_exit — The Clean Shutdown

; exit(0)  — terminates the process immediately, no atexit handlers
    mov  rax, 60              ; SYS_EXIT
    xor  rdi, rdi             ; exit code 0
    syscall
    ; CPU never returns here

Exercises

Warm-up

1. Implement sys_exit with a non-zero error code

Modify syscalls.asm to count the number of bytes written in the first SYS_WRITE call (returned in rax). If the byte count is less than the expected length, call SYS_EXIT with exit code 1; otherwise exit with 0. Run the program and verify the exit code with echo $? after each run.

Core

2. Implement itoa in pure assembly (no libc)

Write print_u64_decimal that converts a 64-bit unsigned integer to decimal ASCII digits and calls SYS_WRITE to print it. Strategy: repeatedly divide by 10 with xor rdx,rdx; div rbx (rbx=10), push remainders, then print them in reverse. Use a 21-byte buffer on the stack (max digits for uint64). This makes your pure-assembly program able to print any number without printf.

Stretch

3. Minimal HTTP request via sys_socket / sys_connect

Using only syscalls, open a TCP connection to 127.0.0.1:8080 and send a minimal HTTP GET request. Syscall numbers: socket=41, connect=42, send=44, recv=45, close=3. Construct the sockaddr_in struct in .bss with the address family (AF_INET=2), port (htons(8080)), and IP (127.0.0.1). Start a listening server with python3 -m http.server 8080 and verify your assembly sends valid HTTP. This is the core of a network tool or reverse shell written entirely in assembly.
