What Is a Register?

The CPU cannot perform arithmetic on data sitting in RAM. Before the ALU (Arithmetic Logic Unit) can add two numbers together, both numbers must be in registers — small, named storage locations built directly into the processor silicon. Reading or writing a register takes one clock cycle. Reading or writing RAM takes tens to hundreds of cycles. Everything your code does ultimately flows through registers.

x86-64 has 16 general-purpose registers, each 64 bits (8 bytes) wide. They are named rax, rbx, rcx, rdx, rsi, rdi, rbp, rsp, and r8 through r15. The names with an r prefix are the 64-bit forms. These are the registers you will use constantly.

But x86-64 didn't start as a 64-bit architecture. It grew from 16-bit (8086, 1978), to 32-bit (386, 1985), to 64-bit (AMD64, 2003). Each generation added wider registers while keeping the old names as aliases into the lower portion of the wider register. This is why reading disassembly is confusing until you have a clear picture of the register layout.

The Register Alias Hierarchy

Every 64-bit register contains within it a 32-bit register, which contains a 16-bit register, which contains two 8-bit registers. They are all the same physical storage — they just refer to different widths of it.

Critical Rule
Writing to the 32-bit sub-register (eax, ebx, r8d, etc.) zeros the upper 32 bits of the full 64-bit register. This is called zero-extension. Writing to the 8-bit or 16-bit sub-registers does NOT zero anything above them. This asymmetry is responsible for a large class of subtle bugs in assembly code.

Tip — Caller vs Callee Saved
Caller-saved registers (rax, rcx, rdx, rsi, rdi, r8–r11) can be destroyed by any function you call. If you need their values after a call, save them first. Callee-saved registers (rbx, rbp, r12–r15) must be preserved by any function that uses them — push them at the start and pop them at the end. Module 09 goes deep on this.

Special-Purpose Registers

rip — The Instruction Pointer

rip holds the address of the next instruction to execute. You cannot write to rip directly with mov — you change it with jmp, call, and ret. However, you can read it indirectly using RIP-relative addressing: [rel label] computes the address of label relative to the current value of rip. This is how position-independent code works.

rflags — The Status Register

rflags is a 64-bit register where individual bits record the outcome of arithmetic operations. You never read it directly — instead, conditional jump instructions (je, jl, etc.) test specific bits of it. The bits you care about most:

Segment Registers — fs and gs

In 64-bit mode the segment registers (cs, ds, ss, es) are mostly vestigial — the OS sets them up and they just hold fixed base addresses of 0. The exceptions are fs and gs, which the OS uses as base pointers for per-thread and per-CPU data.

Security Insight — The TEB
On Windows, gs:[0x30] points to the Thread Environment Block (TEB) — a per-thread structure that contains the stack limits, the thread ID, the last error code, the TLS array, and much more. Shellcode and implants frequently read gs:[0x60] (which is the PEB pointer inside the TEB) to find the loaded module list and resolve API addresses without calling LoadLibrary. On Linux, fs points to the thread-local storage block. Module 15 (System Calls) shows the TEB/PEB walk technique in detail.

Code Walkthrough: registers.asm

; Demo 1 — Zero-extension rule
mov  rax, 0xDEADBEEFCAFEBABE   ; fill all 64 bits
; rax = 0xDEADBEEFCAFEBABE

mov  eax, 0x12345678            ; write to 32-bit sub-register
; rax = 0x0000000012345678  ← top 32 bits ZEROED automatically

; Demo 2 — 8-bit writes preserve upper bytes (no zero-extension)
mov  rax, 0xAAAAAAAAAAAAAAAA    ; set a recognisable pattern
mov  al,  0x11                  ; write lowest byte only
; rax = 0xAAAAAAAAAAAAAA11  ← only byte 0 changed

mov  ah,  0x22                  ; write byte 1
; rax = 0xAAAAAAAAAAAA2211  ← bytes 1 and 0 now changed

mov  eax, 0x55667788            ; 32-bit write → zero-extends
; rax = 0x0000000055667788  ← top 32 bits zeroed again

; Demo 3 — xor eax,eax: the 2-byte zero idiom
mov  rax, 0xFFFFFFFFFFFFFFFF
xor  eax, eax                  ; eax XOR eax = 0; zero-extension clears top 32 bits
; rax = 0x0000000000000000  ← full 64-bit zero in just 2 bytes
Common Mistake
If you write xor rax, rax (using 64-bit operands) instead of xor eax, eax, the result is the same — but it encodes to 3 bytes instead of 2 because the REX.W prefix is required for a 64-bit operand. The compiler always uses xor eax, eax. Prefer it.

Exercises

Warm-up

1. Predict the output

Before running the program, trace through the sub-register aliasing demo on paper. Start with rax = 0xAAAAAAAAAAAAAAAA and apply each instruction in turn. Write down the expected value of rax after each instruction. Run the program and check your predictions.

Core

2. Observe in GDB

Run gdb ./registers and break at main. Enable layout regs. Step through each mov instruction with stepi and watch the register panel update. Pay attention to which registers change and which don't. Specifically: after mov al, 0x11 look at whether rbx, rcx, or any other register changed. They shouldn't — sub-register writes are isolated to that one register.

Core

3. Add bx/bh/bl demos

Add a new demo section in registers.asm that shows the same aliasing behaviour for rbx/ebx/bx/bh/bl. Confirm that writing to bl does not affect bits 63–8, but writing to ebx zeros bits 63–32.

Stretch

4. Read the rflags register

The instruction pushfq pushes the 64-bit rflags register onto the stack. After it, pop rax puts rflags into rax. Add code to: (a) do xor eax, eax, (b) pushfq, (c) pop rax, (d) call print_u64 to show the value. The ZF (bit 6) should be set because the result was zero. Verify: is bit 6 of the printed value 1?

Stretch

5. Encode size comparison

Assemble two versions of zeroing rax: one using mov rax, 0 and one using xor eax, eax. Run objdump -d -M intel registers.o and find both instructions. Count the bytes for each encoding. Confirm that xor eax, eax is exactly 2 bytes and mov rax, 0 is 7 bytes.
