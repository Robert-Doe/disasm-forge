SIMD: SSE, AVX & Packed Data

One instruction, multiple data. SSE2 operates on 2 doubles or 4 floats simultaneously. AVX doubles that to 4 doubles or 8 floats in 256-bit registers. You will understand lane layout, alignment rules, horizontal reduction, and the vzeroupper performance hazard.

Prerequisites — Module 12 (scalar SSE2, xmm registers, float ABI).

What You Will Build

  • simd.asm — SSE2 packed double/float/integer, SSE4.1 blend, AVX 256-bit arithmetic, and a 4-wide vectorized dot product with horizontal reduction

From Scalar to SIMD

Scalar instructions process one value. Packed (SIMD) instructions process multiple values in lanes in parallel. The xmm register holds 128 bits; the ymm register (AVX) holds 256 bits.

The V prefix (VEX encoding) denotes AVX: vmulpd, vaddps. AVX instructions have a 3-operand non-destructive form: vmulpd ymm0, ymm1, ymm2 means ymm0 = ymm1 * ymm2.

Alignment Faults
Using movapd on an unaligned address raises a #GP fault (segfault on Linux). This is actually useful during development — it catches alignment bugs immediately. Always use align 16 or align 32 before SIMD data in .rodata/.data, and ensure rsp is aligned to 16 bytes before call (guaranteed by the ABI) or 32 bytes if you are allocating AVX data on the stack.

SSE2 Packed Double Arithmetic

; addpd — add two pairs of doubles in parallel
    movapd xmm0, [rel pd_a]   ; xmm0 = [2.0 | 1.0]
    movapd xmm1, [rel pd_b]   ; xmm1 = [4.0 | 3.0]
    addpd  xmm0, xmm1          ; xmm0 = [6.0 | 4.0]

; Extract individual lanes
    movsd  xmm2, xmm0           ; xmm2 = lane0 = 4.0
    psrldq xmm0, 8              ; shift right 8 bytes → lane1 now in lane0
                                 ; xmm0 = 6.0

AVX 256-bit: Four Doubles at Once

; vmovapd / vaddpd / vmulpd operate on 4 doubles simultaneously
    vmovapd ymm0, [rel avx_a]  ; ymm0 = [4.0|3.0|2.0|1.0]
    vmovapd ymm1, [rel avx_b]  ; ymm1 = [8.0|7.0|6.0|5.0]
    vaddpd  ymm0, ymm0, ymm1   ; ymm0 = [12|10|8|6] (4 adds, 1 instruction)

    ; Store all four results to memory to inspect
    vmovapd [rel tmp], ymm0

    vzeroupper                  ; REQUIRED before mixing with SSE code
vzeroupper — Never Forget It
On pre-Skylake Intel CPUs, calling SSE code after executing ymm instructions without vzeroupper triggers the "AVX-SSE transition penalty" — up to 100 stall cycles per call because the CPU must merge the upper and lower halves. Always insert vzeroupper before any function call after using ymm registers. The compiler emits it automatically; hand-written assembly must do it manually.

Integer SIMD: 8×16-bit Addition

; paddw: packed add word (16-bit signed integers, 8 per xmm)
    movdqa xmm0, [rel sw_a]   ; [8,7,6,5,4,3,2,1] as 16-bit words
    movdqa xmm1, [rel sw_b]   ; [80,70,60,50,40,30,20,10]
    paddw  xmm0, xmm1          ; [88,77,66,55,44,33,22,11]

; pmullw: packed multiply low word (returns low 16 bits of each 32-bit product)
    pmullw xmm0, xmm1

4-Wide Dot Product with Horizontal Reduction

Computing a·b = a[0]*b[0] + a[1]*b[1] + a[2]*b[2] + a[3]*b[3] using AVX:

    vmovapd ymm0, [rel dot4_a] ; [4|3|2|1]
    vmovapd ymm1, [rel dot4_b] ; [8|7|6|5]
    vmulpd  ymm0, ymm0, ymm1   ; [32|21|12|5]  — 4 multiplies

    ; Reduce 4 lanes to 1 scalar sum:
    ; Step 1: fold upper half down
    vextractf128 xmm1, ymm0, 1  ; xmm1 = [32|21]  (upper 128 bits)
                                   ; xmm0 still = [12|5]  (lower 128 bits)
    addpd   xmm0, xmm1           ; xmm0 = [32+12 | 21+5] = [44|26]

    ; Step 2: horizontal sum the two remaining lanes
    haddpd  xmm0, xmm0           ; xmm0[0] = 44 + 26 = 70.0
    vzeroupper

Exercises

Warm-up

1. Vectorized absolute value

The sign bit of a double is bit 63. Store the mask 0x7FFFFFFFFFFFFFFF in both lanes of an xmm register using pcmpeqw xmm2, xmm2; psrlq xmm2, 1 (set all bits then clear the sign bit). Then use andpd xmm0, xmm2 to clear the sign bit of both lanes simultaneously, computing absolute value for 2 doubles in one instruction.

Core

2. 8-wide integer SIMD: saturating add

Use paddsw (packed add signed word, saturating) instead of paddw. Load two 8-element arrays of int16_t where some pairs overflow int16 (e.g., 30000 + 30000 = 60000, which overflows). Verify that paddsw saturates at 32767 while paddw wraps around. This saturating behavior is important in image processing and audio mixing to avoid wrap-around artifacts.

Stretch

3. Vectorized strlen using SSE2

Load 16 bytes at a time from a string using movdqu xmm0, [rdi]. Use pcmpeqb xmm0, xmm1 (where xmm1 is all zeros) to compare each byte to null, producing a mask. Use pmovmskb eax, xmm0 to extract the comparison mask into an integer register, then bsf eax, eax to find the first set bit. This is the technique used by glibc's optimized strlen on x86-64. Handle alignment at the start and remainder at the end manually.
